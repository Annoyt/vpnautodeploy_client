# План клиента NekoVPN (vpnautodeploy_client)

Статус: **тестовые сборки** (2026-10-10): форк начат до полевого теста по
решению владельца, тестеры первой сборки и есть полевой тест (раздел 8).
Сделано из E13: имя, иконка, пакет, без Firebase, обновления из этого
репозитория, подписанные APK из CI (`CHANGELOG-NEKO.md`). Этот документ — часть
раздела E плана сервера (`docs/IMPROVEMENT_PLAN.md` в
[Annoyt/VPNautodeploy](https://github.com/Annoyt/VPNautodeploy)), вынесенная
в репозиторий клиента: всё, что про приложение, живёт здесь; всё, что про
сервер и подписку, — там. Нумерация задач (E13–E18, E23, E30–E32) общая с
планом сервера.

## 1. Зачем отдельный клиент

- Hiddify оставляет от профиля подписки только список серверов и выбрасывает
  правила, DNS и селекторы (проверено на hiddify-core 4.1.0, закреплённом в
  HiddifyNext 4.1.x). Наша маршрутизация — группа для звонков, carve-out RU
  QUIC, список «всегда через VPN», DNS lockdown-режима — до пользователей
  Hiddify не доходит.
- FlClash (ядро mihomo) применяет профиль целиком. С 2026-10-08 он предлагается
  как второй клиент: `/sub/<token>?format=clash` отдаёт основной профиль в
  форме mihomo (сервер, PR #11).
- Принцип: **всё, что умещается в профиль, делаем на сервере** и получаем на
  всех FlClash-клиентах при обновлении. Форк — только для того, что в профиль
  не умещается: настройки приложения, резервные адреса, кнопка SOS,
  телеметрия с устройства, правки ядра.

## 2. Что берём от FlClash как есть (факты, проверены по исходникам 2026-10-08)

| Факт | Следствие для нас |
|---|---|
| Платформы: Android, Windows, macOS, Linux; **iOS нет** | iPhone остаётся на Karing; клиентская часть плана его не покрывает |
| Профиль обновляется по расписанию пользователя, по умолчанию **раз в сутки**; заголовок `profile-update-interval` не читается | срочное — в `rule-providers`/`proxy-providers` (их интервалы соблюдаются); в форке — удалённая настройка интервала (E14) |
| `geox-url` профиля подменяется настройкой приложения; гео-базы вшиты в APK | свои списки — только через `rule-providers`; источник гео-баз меняется в форке (E14) |
| DNS профиля действует, пока пользователь не включил «Override DNS» | инструкция; в форке — запрет переопределения (E14) |
| `rule-providers` / `proxy-providers` из профиля проходят в ядро | списки, запасной и аварийный каналы работают без форка |
| Импорт по ссылке `clash://install-config?url=…` и по QR | вход в одно касание (E17): из Telegram — через https-редирект на нашем домене |
| «Allow LAN»: прокси-порт для соседей в локальной сети | один хоп «раздать VPN соседям» уже сейчас (E29 на сервере — инструкция) |
| Официального FlClash в **Google Play нет** (пакет `com.follow.clash` отсутствует; «FlClash» в Play — чужая сборка) | раздача: официальный сайт, GitHub-релизы, F-Droid-репо автора; для форка — свой сайт, бот, F-Droid-репо |
| Приложение GPL-3.0; ядро `chen08209/Clash.Meta` (форк mihomo) MIT | форк и переименование допустимы; обязательства — раздел 6 |
| В mihomo **нет фрагментации TLS ClientHello** (`tls.fragment` sing-box) | единственная причина для правок ядра (E18); решает полевой тест |

## 3. Контракт с сервером

Сервер — единственный источник правды о серверах и правилах. Клиент ничего
не хранит сам, кроме того, что нужно для первого подключения и аварии.

### 3.1 Подписка
- `GET /sub/<token>?format=clash` → JSON (подмножество YAML 1.2, mihomo
  читает как обычный профиль). Заголовки: `content-disposition` (имя профиля),
  `subscription-userinfo` (трафик и срок), `profile-title`.
- Содержимое: `proxies` (VLESS-Reality, Hysteria2 с obfs и port hopping,
  VMess/httpupgrade, SS-2022 за ShadowTLS v3, резервный узел для paid),
  `proxy-groups` (VPN / Auto / Calls; позже Cascade — `fallback` в порядке
  каскада), `rules` в порядке sing-box, `dns`, `sniffer`; позже
  `rule-providers` (списки) и `proxy-providers` (запасной и аварийный каналы).
- Токен подписки = идентификатор пользователя во всех остальных вызовах.

### 3.2 Удалённые настройки (E14) — черновик схемы
```json
{
  "version": 12,
  "signed_at": "2026-12-01T10:00:00Z",
  "profile_update_interval_min": 60,
  "lock_mode": "rule",
  "lock_dns_override": true,
  "tun": {"stack": "mixed", "dns_hijack": ["any:53"]},
  "geo": {"auto_update": true, "interval_h": 24, "urls": {"geoip": "...", "geosite": "..."}},
  "endpoints": ["https://a.example/sub", "https://b.example/sub"],
  "emergency": {"provider_url": "https://c.example/emergency", "interval_min": 10}
}
```
- Подпись Ed25519 ключом сервера, публичный ключ вшит в приложение.
  Применяются только подписанные настройки с `version` больше текущей.
- Доставка: HTTPS с нескольких доменов (`endpoints`), затем TXT-запись DNS с
  тем же подписанным документом (DNS блокируют последним), затем копия,
  вшитая в сборку.

### 3.3 SOS-отчёт (E23)
`POST /api/sos` на любой доступный endpoint. Поля со стороны клиента: версия
приложения и ОС, тип сети (Wi-Fi / мобильная), возраст профиля и списков,
результат проверки каждого сервера с текстом ошибки (DNS не ответил, TLS
оборван, таймаут), результаты DNS-проверок, состояние TUN и режима. Сервер
добавляет оператора и страну по IP, трафик по протоколам, пробы по оператору,
состояние DPIMonitor. **Без истории посещений** — только факты о подключении;
об этом честно в описании кнопки.

## 5. Сборка, подпись, раздача

- **CI:** GitHub Actions, матрица как в апстриме: Android (arm64-v8a,
  armeabi-v7a, x86_64), Windows x64 (installer + portable), macOS (Apple
  Silicon + Intel), Linux (deb, rpm, AppImage). Релиз — из тега.
- **Подпись:** Android — свой keystore (пользователи официального FlClash
  обновиться поверх не смогут, нужна переустановка — сказать об этом явно);
  Windows — без сертификата будет предупреждение SmartScreen (сертификат —
  отдельное решение); macOS — нотаризация требует аккаунт Apple ($99/год).
  Ключи и секреты — вне репозитория.
- **Раздача:** наш сайт (страница сама выбирает сборку), бот (APK/exe как
  файл), свой F-Droid-репозиторий. **Не Google Play** (политики и удаления по
  требованию регулятора). Самообновление (E17) — с нашего сервера, с проверкой
  подписи сборки.
- **Версии:** `<версия апстрима>+neko.<N>`; `CHANGELOG-NEKO.md` только про
  наши изменения.

## 7. Как будет устроен репозиторий, когда начнётся код

- История апстрима заливается сюда: `git remote add upstream
  https://github.com/chen08209/FlClash`, `main` = апстрим + наши коммиты;
  слияние `upstream/main` — регулярно (релизы апстрима почти еженедельные).
- Наши изменения — в обособленных местах (`lib/neko/`, `core/neko/`,
  отдельные workflow-файлы), чтобы слияния не конфликтовали.
- Тесты апстрима остаются зелёными; наши — рядом в тех же каталогах.

## 8. Критерий запуска форка

> 2026-10-10: владелец решил начать форк до полевого теста. Тест обычного
> FlClash заменяет тест первой сборки NekoVPN у выбранных пользователей; пункты
> ниже теперь решают, что делать в форке дальше (E15–E18), а не начинать ли его.

Форк начинается только если по итогам полевого теста обычного FlClash из
российских мобильных сетей (E7 плана сервера) верно хотя бы одно:
1. без фрагментации TLS ws или Reality заметно хуже → нужен E18;
2. нужны резервные адреса внутри приложения (домен подписки блокируют) → E15;
3. нужна телеметрия с кнопки (серверных сигналов не хватает) → E16/E23.

Иначе остаёмся на обычном FlClash, а всё управление — через подписку.

## 10. Обновления клиента (E33, E34, E17)

- **Сервер следит за релизами.** Суточная джоба бота опрашивает GitHub Releases
  апстрима `chen08209/FlClash` и (когда появится) этого репозитория, а также
  тег ядра mihomo. На новую версию автоматически прогоняется `mihomo -t`
  нашего профиля на новом ядре; результат и changelog уходят в админ-топик,
  красный прогон = алерт. Так несовместимость профиля с новым ядром видна до
  того, как обновившиеся пользователи начнут жаловаться.
- **Сервер знает версии клиентов** по User-Agent запросов подписки и напоминает
  об обновлении не чаще раза в неделю.
- **В форке:** проверка обновлений при каждом запуске с нашего сервера, подпись
  сборки проверяется до установки; для критичных версий — принудительное
  обновление (E17).

## 11. Страница загрузки и подпись (E35)

- Страница на нашем домене определяет платформу и отдаёт нужный файл: сборки
  апстрима с GitHub Releases сейчас, наши подписанные — когда появятся; QR на
  импорт подписки; инструкция в три шага; честное предупреждение о SmartScreen
  и Gatekeeper, пока сборки не подписаны.
- Подпись сборок (сертификат Windows, аккаунт Apple для нотаризации) — позже,
  отдельным решением владельца; ключи вне репозитория.
- Страница покрывается Playwright E2E отдельной стадией, как дашборд сервера.

## 12. Тесты и качество

Клиент покрывается тестами так же, как сервер, красное не мержится:
- юнит- и виджет-тесты Flutter на весь наш код (удалённые настройки, SOS,
  шлюз, память сетей), тесты апстрима остаются зелёными после каждого слияния;
- интеграционные тесты: подпись и версия удалённых настроек (подмена, откат
  версии, битый документ), перебор каналов SOS с недоступными адресами,
  импорт профиля из файла и по ссылке;
- Playwright для страницы загрузки;
- CI на каждый PR в этом репозитории: тесты, сборка под все платформы,
  проверка лицензионных пометок; приём «верни баг — проверь красноту» для
  ключевых условий, как на сервере.
